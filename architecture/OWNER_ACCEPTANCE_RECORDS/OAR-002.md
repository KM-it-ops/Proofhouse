# OAR-002 — Owner ratification of the MISSION-008 Requirements Compiler contract direction

**Status:** Accepted and binding
**Ratified:** 2026-07-25
**Owner authority:** Project Owner (Mahmoud / `KM-it-ops`)
**Mission:** MISSION-008 — Requirements Compiler Contract and Evidence Model

## Purpose and authority

This record captures the Project Owner's explicit acceptance of the ten `RCD-008-*` decisions proposed
in `architecture/requirements-compiler-contract-v0.1/DECISION_LOG.md` and requested in
`OWNER_DECISION_REQUEST.md`. It is an authorization record, not an implementation authority and not a
replacement for an ADR.

The MISSION-008 contract package explains the reasoning, evidence, and boundaries. This OAR establishes
that the owner has accepted the listed decisions as the ratified contract direction for the requirements
authoring-to-IR boundary.

## Ratified decisions

### OAR-002-01 — RCD-008-001, requirements and evidence model

The source-language-neutral requirements document and evidence bundle are the canonical boundary between
authoring input and frozen PromptRig IR v0.1.

### OAR-002-02 — RCD-008-002, authority order

The accepted precedence is owner decision → user decision → accepted contract → source evidence →
authorized default → deterministic derivation → model proposal → provider constraint → implementation
convenience. Lower-ranked input cannot silently override, erase, reinterpret, or weaken higher-ranked
authority. Per `AD-003`, an owner/user conflict is established only by structured conflict evidence — an
unresolved `conflicts` record whose `authority_ranks` span `owner` and `user` — never by the wording or
formatting of authoring labels.

### OAR-002-03 — RCD-008-003, defaults

Defaults are permitted only when visible, scoped, non-conflicting, and attributable, and require explicit
resolved approval when consequential. This ratifies the default *regime*; it approves no actual
consequential default.

### OAR-002-04 — RCD-008-004, deterministic and model-assisted boundary

Deterministic validation establishes structural and contract validity. Semantic acceptance additionally
requires a permitted authority basis and attributable source evidence. Model-assisted output remains
proposal-only until separately accepted through an attributable decision record. No model call is
authorized.

### OAR-002-05 — RCD-008-005, terminal statuses

`SUCCESS`, `PARTIAL`, `BLOCKED`, `REFUSED`, and `INVALID_OUTPUT` are the accepted distinct terminal
statuses for a validation attempt, with RC-060 through RC-064 semantics. A canonical attempt's terminal
status is a function of its canonical record set alone and must be recomputable from those records.

### OAR-002-06 — RCD-008-006, diagnostic namespace

The separate, versioned `RQC-*` Requirements Compiler diagnostic namespace is accepted. The frozen
Compiler Core registry at `architecture/diagnostics/DIAGNOSTIC_CODE_REGISTRY.json` is unchanged, and the
proposed `RQC-*` codes are not added to it.

### OAR-002-07 — RCD-008-007, security, privacy, and approvals

Security, privacy, and approvals are first-class requirements. Consequential uncertainty, missing
authority, and missing approval fail closed. Security semantics follow the canonical requirement `type`,
never identifier text.

### OAR-002-08 — RCD-008-008, requirement-to-IR traceability

Every requirement maps to exact frozen IR v0.1 JSON Pointers or to an explicit
unresolved/prohibited/gap outcome, and every emitted IR leaf traces to accepted meaning, an authorized
default, or a permitted deterministic derivation.

### OAR-002-09 — RCD-008-009, PRS disposition `DEFERRED`

The accepted disposition for PRS is **`DEFERRED`**, pending representative syntax, source-map, grammar,
complexity, and value evidence. Ratifying this decision ratifies the deferral itself: **ADR-001 is
unchanged**, PRS is not accepted contract syntax, and no PRS grammar, parser, formatter, or language
server is authorized.

### OAR-002-10 — RCD-008-010, IR v0.1 gaps

`IRG-008-001` and `IRG-008-002` are carried into separately authorized Roadmap Phase 5 planning as
blocked requirements evidence. Frozen IR v0.1 is unchanged and no IR v0.2 shape is accepted.

## Binding scope

These decisions are binding as the ratified **contract direction** for the requirements
authoring-to-IR boundary: the requirements document and evidence bundle shape, authority and default
semantics, the deterministic/model-assisted boundary, terminal statuses, the `RQC-*` diagnostic
namespace, security/privacy/approval handling, and requirement-to-IR traceability.

## Explicit non-authorizations

This ratification does **not**:

- implement a requirements compiler, ordinary-language parser, PRS grammar or parser, or any model call;
- authorize evaluation, repair, live execution, benchmarks, UI, API, persistence, tenancy, billing,
  hosted infrastructure, providers, credentials, or permissions;
- change PromptRig IR v0.1, the frozen Compiler Core diagnostic registry, generated contracts, frozen
  contracts, historical evidence, CI, packages, or tags;
- change ADR-001 or accept PRS as contract syntax;
- accept an IR v0.2 shape or authorize ADR-007;
- begin MISSION-009, MISSION-010, or MISSION-011;
- self-certify or promote the Requirements compiler capability;
- **merge PR #13, enable auto-merge, mark it ready for review, or authorize release or tags.**

Merge, release, capability promotion, and later missions remain separate explicit gates.

## Open items not resolved by this ratification

Ratification covers direction, not every refinement. The following remain open and are unaffected:

- `OQ-008-001` through `OQ-008-010` remain open. `OQ-008-003` (approval-authority thresholds) is the
  operationally significant one: required authority continues to resolve from an accepted
  approval-threshold policy, and undeterminable authority remains `BLOCKED` rather than assumed.
- Semantic equivalence between a preserved source fragment and a requirement statement remains a
  **manual review** obligation. Deterministic validation proves provenance, never equivalence.
