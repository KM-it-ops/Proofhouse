## Status vocabulary

| Status | Meaning |
|---|---|
| `CERTIFIED` | The stated narrow capability is implemented or governed, merged, covered by behavior-level evidence, and included in explicit independent review or re-certification. |
| `IMPLEMENTED_NOT_CERTIFIED` | Code or automation exists and has tests, but the capability boundary lacks explicit independent certification or consumer proof. |
| `PARTIAL` | A useful subset exists; major semantics or required surfaces are absent. |
| `CONTRACT_ONLY` | A current accepted contract constrains behavior, but the product capability is not implemented. |
| `PROPOSED` | Design intent exists but is not ratified as an executable contract. |
| `DEFERRED` | Work is intentionally held behind named dependencies. |
| `NOT_STARTED` | No qualifying current contract or implementation exists. |
| `REJECTED` | The interpretation or commitment is explicitly disallowed. |

Certification never expands scope. An offline lowering adapter can be certified as an offline lowerer while live provider execution remains absent.

## Capability summary

The certified center currently begins with already-formed PromptRig IR and ends with offline provider-shaped artifacts plus evidence. The missing product arc is intent reconstruction before IR and evaluation/repair after lowering. Hosted delivery, runtime execution, benchmark operations, and downstream products remain outside the certified boundary.

## Promotion rule

A capability changes status only through a repository change that updates this map, identifies exact evidence, passes its phase gates, receives independent architectural review, and obtains explicit owner approval when architecture or roadmap authority changes. MISSION-010 may prove a bounded prototype profile but cannot certify production requirements, evaluation, repair, evidence, library/CLI, packaging, or consumer readiness. Those boundaries can be promoted only after the MISSION-011 traceability, deterministic/adversarial/security/regression, repair-budget, packaging, clean-install, external-consumer, cross-platform, performance/resource, independent-certification, and owner-approval gates pass. Mentions in plans, prototypes, historical reports, or green CI do not promote maturity.
